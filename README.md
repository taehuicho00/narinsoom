# 나린숨 예약관리 마스터 사이트

양평 '나린숨' 펜션에서 실제로 운영하는 입실 정보 수집·직원 현황판입니다.

## 해결한 문제
- 손님 답장(인원·반려견·입실시간·숯불)을 확인하려고 직원이 사장에게 계속 전화함
- 예약 채널 번호가 050 안심번호라 답장이 와도 몇 호실 손님인지 구분이 안 됨
- 자유 형식 답장을 사람이(또는 봇이) 해석하다 보니 추가요금 계산 오류가 생김

## 동작 방식
1. 매일 저녁 봇(Python)이 예약관리 시스템(PMS)에서 다음 날 입실 예약을 읽어 예약마다 무작위 코드를 만들고 DB에 저장
2. 코드가 담긴 링크를 문자로 발송 → 손님은 버튼 몇 번으로 입실 정보 제출
3. 직원은 `/staff/` 화면에서 주 단위로 응답 여부·내용·추가요금을 바로 확인
4. 사장 미리보기 후 추가요금 안내 문자 발송, 직원 화면에서 입금 확인

## 구성
| 위치 | 내용 |
|---|---|
| `index.html` | 손님용 입실 정보 페이지 (`?c=코드`) |
| `staff/index.html` | 직원용 현황판 (4자리 비밀번호) |
| `assets/config.js` | Supabase 주소·공개 키 |
| `supabase/migrations/` | DB 설계 SQL (표, RLS 정책, 함수) |

- 프론트엔드: HTML/CSS/JavaScript, GitHub Pages 배포
- 백엔드: Supabase (PostgreSQL, Auth, Row Level Security)
- 자동화: Python 봇 (PMS 조회, 솔라피 문자 발송) — 별도 저장소

## 보안·개인정보 설계
- 손님(비로그인)은 표에 직접 접근 불가, `get_reservation` / `submit_response` 함수로 **자기 코드의 예약만** 조회·제출
- 제출 값은 서버 함수에서 다시 검증 (객실별 최대 인원, 반려견 불가 객실, 입실·숯불 가능 시간, 번호 형식·동의)
- 직원 화면은 4자리 비밀번호(bcrypt 해시 저장) → 30일 기기 토큰 발급, 같은 IP 15분 5회 실패 시 잠금
- 직원 화면도 표에 직접 접근하지 않고 `staff_week` / `staff_set_paid` 함수로만 조회·입금 확인
- 전화번호는 050 안심번호 손님에게만, 동의를 받아 수집하고 퇴실 30일 후 삭제

## 로컬에서 보기
정적 파일이라 별도 빌드가 없습니다. `python3 -m http.server` 후 `http://localhost:8000/?c=코드`
